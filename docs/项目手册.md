## 2. 功能与权限

### 2.1 两种角色 + 可勾选权限

角色只有「管理员 / 成员」两种，运营能力由管理员逐项勾选：

| 权限键 | 说明 |
|---|---|
| `finance` | 经费台账（记账、收付款审核、账单导出） |
| `equipment` | 设备台账、预约审核、维护、打印任务、设备日志导出 |
| `inventory` | 耗材、元器件库存、仪器借还 |
| `access` | 门禁申请审核、授权与进出登记 |
| `activity` | 活动发布、报名与签到 |
| `duty` | 值班排班与签到 |
| `doc` | 资料归档与下载 |
| `api` | 签发/管理 API Key，供外部系统调用接口 |

- 管理员默认拥有全部权限，不可被取消；成员按需勾选。
- 拥有 `finance` 时还需单独开关「可录入收入 / 可录入支出」，至少保留一项。
- 普通成员不强制改密，仅在页面顶部提示；管理员首次登录强制改密。
- 权限后端逐接口校验，前端隐藏只是体验层。
- 旧版本的「财务员」角色已并入成员：数据库迁移会自动把 `role='finance'` 转为 `member` 并补上 `finance` 权限；接口仍兼容传入 `role:'finance'`。

### 2.2 收支规则

- 金额以「分」为单位存整数（`amount_cents`），避免浮点误差。
- 并发安全三件套：
  1. SQLite WAL + `BEGIN IMMEDIATE` 同步事务；
  2. 每条账单带 `version`，`UPDATE ... WHERE id=? AND version=?`，`changes=0` 返回 409；
  3. 客户端 `client_request_id` 幂等键，重复提交只入账一次。
- 删除为软删除（`deleted_at`），余额实时聚合，不存冗余余额。
- 凭证最多 12 张/条，类型白名单，鉴权后访问。

### 2.3 收款台账规则

- 状态：`collections.status` 为 `open | closed`；缴纳记录 `pending | approved | rejected`。
- 每人每台账只有一条缴纳记录（`UNIQUE(collection_id, user_id)`）。
- 已被驳回可重新提交（覆盖旧记录并替换附件）；待审核/已通过不可重复提交。
- 审核通过可勾选「计入班费收入」，**默认计入**；生成收入账单时 `client_request_id = collection-payment:{id}` 防重复。
- 「全部通过」在单个事务里处理全部 pending，任一条被并发审核则整体回滚返回 409。
- 已有缴纳记录时禁止修改台账金额。
- 缴纳凭证仅本人或有审核权限的人可看。

鉴权优先级：
1. `X-API-Key: cfk_...` 或 `Authorization: ApiKey cfk_...`（外部调用，继承成员权限，单密钥每分钟 120 次，可用 `API_RATE_LIMIT` 调整）；
2. `Authorization: Bearer <token>`；
3. Cookie `cf_token`（前端默认）；
4. 下载链接可带 `?token=`。

跨域仅在 `CORS_ORIGINS`（逗号分隔）命中时回写 CORS 头，默认关闭。

## 8. 经验与踩坑

1. **`better-sqlite3` 装不上**：服务器/本机安装脚本被拦截，原生模块编译失败。改用 Node 内置 `node:sqlite`（`DatabaseSync`），零原生依赖。要求 Node ≥ 22.5，Docker 用 `node:24-alpine`。
2. **并发写冲突**：单靠 SQLite 默认事务不够。使用 WAL + `BEGIN IMMEDIATE`，写操作串行化。
3. **两个人同时改同一条账单**：前端带 `version`，后端 `WHERE version=?`，失败返回 409 并提示刷新，避免后写覆盖先写。
4. **重复点击提交导致重复入账**：前端生成 `clientRequestId`，后端唯一索引兜底，重复请求返回原记录。
5. **台账审核重复入账**：审核时先查 pending，事务内插入收入账单并用 `WHERE status='pending'` 更新；`changes=0` 整体回滚。账单幂等键用 `collection-payment:{id}`。
6. **中文文件名乱码**：multer 的 `originalname` 常是 latin1，需 `Buffer.from(name, 'latin1').toString('utf8')`。
7. **测试污染真实数据**：测试文件在导入应用前设置临时 `DATA_DIR`，并设固定 `JWT_SECRET`。
8. **ESLint 报 `react-hooks/exhaustive-deps` 不存在**：未装该插件，移除 disable 注释；扁平配置按 Node/浏览器环境分组。
9. **Prettier 全量检查失败**：先 `npx prettier --write` 统一格式，再跑 lint/build/test。
10. **PowerShell 不支持 `&&`**：用 `;` 串联；`$LASTEXITCODE` 判断前一条命令结果。
11. **重启报 `EADDRINUSE 8787`**：`StopCommand` 可能没真正结束进程，用 `Get-NetTCPConnection -LocalPort 8787` 找 PID 后 `Stop-Process -Force`。
12. **Nginx 与 Docker 抢 80**：先把 compose 端口改为 `127.0.0.1:8787:8787`，再安装/启动 Nginx，否则 Nginx 起不来。
13. **Docker 构建超过命令超时**：构建会转入后台，用 `sudo docker ps` 和 health 接口确认结果，不要重复执行 compose。
14. **PowerShell 发中文 JSON 乱码**：显式使用 UTF-8 编码，或改用 Node `fetch` 验证接口。
15. **线上登录失败不一定是 Bug**：本地管理员密码可能已被修改；线上是全新库，初始密码 `Admin@123456`。

## 9. 安全与后续路线

- 当前为 HTTP。上线小程序/长期使用前建议：
  1. 腾讯云购买域名并完成 ICP 备案；
  2. 解析 A 记录到 `1.14.125.216`；
  3. Nginx 配 443 + 免费证书（Let's Encrypt 自动续期），80 跳 443；
  4. 小程序后台配置 request / uploadFile / downloadFile 合法域名。
- 小程序方案：推荐 Taro（React 语法）；登录改用 `wx.login` + `code2session` 绑定 openid，接口用 Bearer token，不需要 Cookie。
- 小程序导出：`wx.downloadFile` + `wx.openDocument`；或 web-view 打开 H5 导出页（需业务域名）。
- 微信支付：当前「线下转账 + 上传凭证 + 审核」不需要支付资质；若要做在线缴费，需企业主体 + 商户号。
- 微信云托管：容器无持久磁盘，用 SQLite 需改 MySQL；小规模下自购域名 + 现有服务器更划算。
- 可继续做的功能：未缴名单/催缴清单、台账单独导出、审核生成的收入账单补分类、余额预警、只读分享链接、多班级/多学期。
